# Арт-Маркет API

Бэкенд для макета `artMarketProjectUi`: регистрация, маркеты, избранное, резюме мастера и заявки на участие.

Стек: Python, FastAPI, SQLAlchemy, PostgreSQL 16. Схема создаётся при старте приложения, отдельный образ базы не нужен — в Compose используется официальный `postgres:16-alpine`.

Интерфейс в `artMarketProjectUi` по-прежнему работает на данных из `scripts/app.js` и к этому API сам не обращается.

## Запуск

Из каталога `ArtMarketProject`:

```powershell
docker compose up --build
```

API: http://localhost:8000  
Документация: http://localhost:8000/docs

Остановить и удалить данные:

```powershell
docker compose down -v
```

Тестовый пользователь из макета: `test` / `1111`. В кабинете имя берётся из первого резюме — «Терракотовый сад».

В Swagger вызовите `POST /api/auth/login`, скопируйте `access_token` и вставьте его в Authorize.

Чтобы поднять только базу и запустить API локально:

```powershell
docker compose up db -d
python -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
uvicorn app.main:app --reload --port 8000
```

Переменные лежат в `.env.example`. Для локального `uvicorn` подходит адрес `localhost` из этого файла. `JWT_SECRET` в Compose — только для разработки.

## Данные

Три маркета, пользователь `test`, два резюме и три заявки повторяют макет.

Даты взяты с карточек афиши, год — 2026. На экране заявки у «Цветочного» в вёрстке стоит другая дата (15–16 мая); API её не использует.

Полный текст «О маркете» в макете есть только у «Арт-Двора». У «Цветочного» и «Весны» короткие описания по их тегам. Адрес, организатор и приблизительные координаты тоже заданы только у «Арт-Двора».

У резюме в макете нет файлов фотографий, только число слотов: 3 и 5. В базе это пустые слоты (`null`), `photo_count` равен длине списка. Ссылок на картинки там нет. В запросе можно передать до 6 URL.

Повторная заявка того же пользователя на тот же маркет отклоняется. Статус новой заявки — `pending`. Поменять статус через API нельзя: в макете мастер статус только смотрит.

Пока база пустая, наполнение выполняется при старте. Если маркеты уже есть, повторно оно не запускается.

## Методы

Авторизация не нужна для списка и карточки маркета. Если передать токен, в ответе будут `is_favorite` и `my_application`.

| Метод | Путь | Доступ |
| --- | --- | --- |
| POST | `/api/auth/register` | нет |
| POST | `/api/auth/login` | нет |
| GET | `/api/auth/me` | токен |
| GET | `/api/markets` | нет |
| GET | `/api/markets/{id}` | нет |
| GET | `/api/favorites` | токен |
| POST | `/api/favorites/{market_id}` | токен |
| DELETE | `/api/favorites/{market_id}` | токен |
| GET, POST | `/api/resumes` | токен |
| GET, PATCH, DELETE | `/api/resumes/{id}` | токен |
| GET, POST | `/api/applications` | токен |
| GET | `/api/applications/{id}` | токен |
| GET, PATCH | `/api/me` | токен |
| GET | `/api/health` | нет |

Поиск: `GET /api/markets?q=керамика&city=Санкт-Петербург`. Параметр `upcoming=true` оставляет только маркеты, которые ещё не закончились.

Ошибки, которые макет показывает на формах, приходят строкой в `detail`: «Неверное имя или пароль», «Имя должно быть от 3 символов», «Пароль минимум 4 символа», «Такой пользователь уже существует».

Поле карточки `meta` собрано так же, как подпись на афише, например `📅 8 июня, 12:00–22:00 · Санкт-Петербург`. В `detail_meta` перед городом стоит маркер места.
